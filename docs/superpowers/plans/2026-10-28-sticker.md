# Sticker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver a private Docker-installable issue tracker for an owner and coding agents.
**Architecture:** Express/React single TypeScript app; SQLite, private disk uploads; official MCP STDIO adapter over authenticated API.
**Tech Stack:** Node 24, TypeScript, React, Vite, Express, Zod, node:sqlite, official @modelcontextprotocol/sdk 1.x.
**Spec:** docs/superpowers/specs/2026-10-28-sticker-design.md

## Global Constraints

See the verbatim Global constraints section in the spec; all apply to every task. App name is 스티커 (Sticker); UI labels are Korean. Private owner plus coding agents; no team invitations. Default binding 127.0.0.1:8787, required configured auth; no live credential generation. Waiting never autoruns. Agent reports are timestamped self-reports; stale after five minutes. Only owner closes issues. Browser/MCP use same domain checks. Versions must belong to project.

## Review Focus

1. Scope escape via issue/project/version IDs is rejected (domain and API tests).
2. Credential/session expiry, cookie cross-origin writes and forged attribution are rejected (API tests).
3. Restart preserves relational data and private file records (domain/API tests).
4. Unsafe link/file content and traversal never become executable/servable outside attachment root (API tests).
5. Mobile detail panels, cancel/reopen and error/repeated actions remain usable (browser tests).
