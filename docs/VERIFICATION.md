### 기능·안전성 범위

- 실제 임시 SQLite DB를 사용한 프로젝트/버전/이슈 CRUD, 잘못된 프로젝트·버전 관계, 읽기 전용·프로젝트 제한 권한 검증.
- 이슈 `revision` 충돌, 담당자 동시 수정 충돌, 구현 완료와 소유자 종결 구분, 사칭할 수 없는 작성자/활동 기록.
- 비밀번호 없는 실행 거부, 세션 만료/로그아웃, HttpOnly/SameSite 쿠키, 외부 Origin 쓰기 차단, 로그인 실패 제한.
- 비공개 파일 업로드·다운로드, 20 MiB 제한, HTML 강제 다운로드, 감지된 안전한 래스터 이미지 미리보기, 한국어/RFC5987 파일 이름, 잘못된 multipart 처리.
- **서버를 완전히 닫았다 다시 열어도** 이슈·댓글·파일 바이트가 유지되며 이전 로그인 세션은 무효가 되는지 확인.
- 공식 MCP SDK **1.32.2** 클라이언트가 실제 STDIO 어댑터에 연결하여 초기화, 도구 목록, 도구 호출 수행. 어댑터 → 실제 HTTP API → SQLite/파일 저장 경로 확인. 최대 **5 MiB** 파일 업로드와 다시 읽기 검증.
- React를 실제 DOM(jsdom)에 마운트하여 실제 HTTP API와 연결: 로그인/로그아웃, CRUD, 댓글/링크, 다시 마운트한 뒤 유지되는 데이터, 취소/Escape/포커스, 보드 열의 기본 상태, 충돌 시 초안 보존·명시적 확인, 중첩 창 종료 시 스크롤 복구 확인.
- 백업/복원은 **가짜 Docker 명령으로 오케스트레이션을 검증**하면서 실제 SQLite·파일·tar를 사용. 파일 권한, 덮어쓰기/확인 게이트, 경로 탈출/링크 거부, 무결성/스키마/FK/첨부 파일 크기 검사, 잘못된 백업에 기존 데이터 보존 확인.

## 독립 검토

백엔드 검토와 별도 통합 검토를 수행했습니다. 검토에서 발견한 잘못된 백업의 데이터 손실 위험, MCP 대용량 검증 오류, 모바일 로그아웃, 충돌 복구, 중첩 모달 스크롤 잠금 문제를 회귀 테스트와 함께 수정했습니다. 최종 검토에서 남은 Critical/Important 지적은 없습니다.

## 실행하지 못한 검증

1. **실제 Docker 이미지 빌드·컨테이너 실행**: 이 실행 환경에는 Docker 실행 파일/데몬이 없습니다. Dockerfile/Compose 정적 검토와 스크립트 fixture 검증만 수행했습니다. `docker compose up -d --build`의 실제 결과를 확인했다고 주장하지 않습니다.
2. **실제 브라우저 렌더링·desktop/iPhone E2E·스크린샷**: Chromium 실행이 sandbox의 socket 권한 오류(EPERM)로 차단되었습니다. 다른 경로로 우회하지 않았습니다. DOM 테스트는 통과했지만 픽셀 레이아웃, 실제 iPhone Safari, 브라우저 파일 선택/다운로드 동작의 시각적 검증을 대신하지 않습니다.

## 운영 경계

공개 서비스 배포, 원격 저장소/이미지 게시, 실사용 비밀번호·토큰 발급, 권한 부여, 사용자 설정 변경은 수행하지 않았습니다. 기본 설치는 빈 개인 작업 공간입니다. 운영자는 README대로 본인의 비밀번호를 설정해야 합니다. 이 앱은 에이전트를 실행하지 않으며 대기 이슈를 자동 시작하지 않습니다.

## 자료실 네이티브 회귀 실행 (schema7)

`npm test`에는 공통 자료의 계약/서비스/실제 HTTP/공식 MCP 클라이언트와 `tests/container-resources.test.ts`가 포함됩니다. 마지막 테스트가 `container-resources-smoke.mjs`를 실제 임시 서버에서 실행해 공유 파일의 두 버전, 한 연결 해제, tombstone, 재시작과 복원 후 이전 바이트·정확한 이슈 목록을 확인합니다. 가짜 Docker 테스트나 실제 Docker 실행 결과로 바꾸어 표현하지 않습니다.

물리적 부분 쓰기 실패 회귀는 일반 데이터베이스·사용자 서버를 사용하지 않습니다. POSIX 저장소 단위 검사는 Bash `ulimit`을, 기존 HTTP 첨부의 Linux 검사는 util-linux의 `prlimit`을 사용해 새로 만든 자식 프로세스만 제한합니다. Windows에서는 POSIX 주입을, Linux 외에서는 `prlimit` 주입을 명시적으로 건너뜁니다. 이 도구는 개발/CI의 실패 주입용이며 실행 중인 앱이나 Docker 런타임의 추가 의존성이 아닙니다. 지원 플랫폼의 실제 결과와 건너뜀을 구분해야 합니다.
