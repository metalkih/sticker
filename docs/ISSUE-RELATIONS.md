# 이슈 관계

같은 프로젝트의 이슈를 부모/하위, 관련, 차단/피차단 관계로 연결합니다. 이슈 상세의 **관계 추가**에서 관계 종류와 검색 결과를 선택합니다. 카드와 목록은 차단 원인으로 바로 이동하는 버튼 및 하위 이슈의 구현 완료(`done`)·소유자 종결(`closed`) 개수를 별도로 표시합니다.

## 의미와 권한

- 부모→하위, 선행→피차단 방향입니다. 관련 관계는 방향이 없습니다.
- 한 이슈의 부모는 하나이며 자기 참조, 부모 순환, 차단 순환 및 다른 프로젝트 연결은 거부됩니다.
- 선행 이슈가 `done`이어도 차단 상태입니다. 소유자가 `closed`로 종결해야 해소됩니다. 관계 해소는 실행 승인이나 자동 시작이 아닙니다.
- 하위 이슈가 모두 완료·종결되어도 부모 상태를 자동 변경하지 않습니다.
- 부모 삭제는 관계만 제거하며 자식은 보존됩니다. 생존 이슈에 제거 주체와 시각이 기록됩니다.
- 모든 조회와 변경은 현재 프로젝트 범위를 확인합니다. 읽기 전용 에이전트는 변경할 수 없고, 종료된 이슈의 관계는 소유자만 변경합니다.
- 관계 변경은 양쪽 이슈의 현재 revision을 검사하고 같은 트랜잭션에서 양쪽 revision과 활동 기록을 갱신합니다. 충돌은 409이며 선택을 보존합니다. 최신 상태를 확인한 뒤 다시 시도하세요.

## HTTP / MCP

- `GET /api/issues/:id/relations`: 부모·하위·관련·차단 원인·피차단 대상과 하위 상태별 개수.
- `GET /api/relations/summary?projectId=...`: 현재 권한 내 이슈 요약을 한 번에 조회. 화면 카드별 N+1 요청을 하지 않습니다.
- `POST /api/issues/:id/relations`: `{kind: "parent"|"blocks"|"related", targetIssueId, sourceRevision, targetRevision}`. 경로의 이슈가 source입니다.
- `DELETE /api/relations/:id`: `{sourceRevision,targetRevision}`. 조회 결과의 canonical source/target에 해당하는 revision을 전달합니다. 이슈 데이터는 삭제하지 않습니다.
- MCP: `sticker_get_issue_relations`, `sticker_add_issue_relation`, `sticker_remove_issue_relation`. HTTP와 같은 권한·순환·충돌 검사를 사용합니다.

## 저장과 복구

마이그레이션 3은 관계 테이블과 인덱스만 추가합니다. 기존 이슈, 세션, 댓글, 첨부는 그대로 유지됩니다. 백업 검증기는 스키마 1·2·3을 읽기 전용으로 검증하고, 유효한 이전 백업을 복원한 다음 정상 시작 과정에서 마이그레이션합니다. 관계와 새 활동 기록은 재시작 후에도 유지됩니다.

## 검증 범위

도메인·실 HTTP·공식 MCP SDK·DOM 회귀 테스트가 포함됩니다. `tests/ui/relations.spec.ts`는 실제 Chromium에서 검색/연결/차단 원인 이동/키보드와 375px 화면을 검증하도록 작성되었습니다. 실제 브라우저 및 컨테이너 실행 결과는 해당 커밋의 CI 결과로 확인해야 하며, DOM 테스트만으로 시각 검증 통과를 주장하지 않습니다. 테스트는 임시 데이터와 fixture 인증만 사용하며 개인 경로·계정·기존 설치에 의존하지 않습니다.
